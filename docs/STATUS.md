## Gates that remain open

1. **Six-model proof:** source-complete SANISAND-2004 extraction; declarative load-reversal/history events and initialization; independent numerical reference comparisons. The existing five models do not close this gate.
2. **Representation v1:** event semantics/rollback; general vector/anisotropic fourth-order quantities; source-specific timed kinematics/capability declarations beyond the experimental ODE schedule/observable contracts; stress-measure/objective-rate declarations. Define extensions only against source-complete examples. Current YAML support is the JSON subset.
3. **Initialisation/tangents:** richer state initialization from consolidation history and a public consistent algorithmic tangent API. Current mixed controls use finite-difference update tangents.
4. **Literature review:** screen/deduplicate discovery records; perform citation tracing; source-pin exact remaining variants; record equation-level provenance and reviewers. Candidate criteria/families are not complete constitutive models.
5. **Twenty executable formulations:** select from the twenty-six research candidates, then transcribe and independently verify the chosen formulations or explicitly revise the shortlist based on source availability and scientific relevance. Do not pad the count with unnamed modifications.
6. **Data breadth:** extract initial/preparation metadata; implement cyclic sand and kaolin importers with reviewed mappings. Original TMU files omit e0; do not invent it. Review redistribution terms before bundling original data anywhere.
7. **Calibration study:** freeze whole-test calibration/held-out splits, objectives, bounds, algorithms, seeds and budgets; reproduce published baselines before fitting; include numerical failures and parameter uncertainty in comparisons.
8. **Scientific release:** establish novelty against MFront and related tools; complete analysis, authorship, independent review and manuscript; archive a reproducible version and obtain a DOI when ready. The private software preview is not that release.

## Known limitations

Current local verification: the catalogue checks and nine new evidence/oracle tests pass in addition to the prior solver suite; the C++ Jacobian/covariance suite and the new C++ temporal analytical suite pass. Native/WebAssembly parity passes for 25 existing model/protocol combinations and five temporal success/failure cases, plus six timed-schedule success/failure cases and algebraic observation, and five Terracotta author-RHS research histories. The physical-time tests use a separate synthetic catalogue, with exponential relaxation, scalar nonautonomous evolution, varying stage rates, refinement and full-update rollback. Separate analytical schedule checks now exercise numerically solved creep controls, Kelvin–Voigt ramp/hold response, rate jumps, mixed controls, targets, replay/restart and rollback. They do not establish Terracotta correctness. Prior browser verification covers experimental overlay import/toggling and ordinary laboratory runs. GitHub Pages is the primary public deployment.

The early-strain benchmark uses a monotonic ramp and curve interpolation, not exact replay of pauses or nonmonotonic recorded paths. Exactly repeated strain samples use the last observation; reversing histories are rejected. Hypoplastic IGS parameters in the UI are illustrative defaults, not the published KFS baseline used for the base-law demonstration. Numerical agreement among interpreter/native/Wasm paths does not independently establish equation correctness.

The language's current state limit is 24 scalars, and v0.1 declared units are `1` and `Pa`; the experimental v0.2 ODE schema additionally supports time/temperature and bounded rational SI exponents. Legacy integration tolerances/limits remain fixed; the experimental temporal update exposes documented error/step settings. The no-dependency dense solver replaces the plan's initial Eigen choice for native/Wasm portability. Built-in LaTeX compilation did not return during verification; the supplied PDF was compiled successfully using the installed TeX toolchain and visually inspected instead.
