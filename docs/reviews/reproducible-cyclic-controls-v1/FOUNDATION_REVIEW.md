# Additive literal-control foundation review

The parent's revised explicit bit-wire API is the recommended first implementation; the deterministic producer is separate prospective work.

Proposed function: `atlas_run_controls_with_settings(id,parameters,initial,protocol,controls_bits_csv,settings_csv)`, with distinct experimental APIversion and `loading.version="laboratory-controls-0.1"`, `loading.encoding="ieee754-binary64-hex"`. Each CSV token is exactly16 lowercase hexadecimal digits representing one uint64 IEEE binary64 bit pattern. There are2..5001 cumulative targets including the initial exact signed zero. All targets must be finite and satisfy existing protocol cap(.1 strain;1e8Pa q). One target is consumed per existing controller call; no interpolation/snap, no new constitutive equations. Shared original run loop receives optional literalcontrols to avoid controller duplication. Old APIs/browser/import behavior and old failed gates remain unchanged.

This resolves decimal/subnormal parser ambiguity and negative-zero re-export ambiguity, provided controls_bits remains authoritative and numeric controls is expressly a plotting convenience. Numeric metadata alone is not sufficient to reconstruct signed zero. Initial ±0 may be accepted and preserved: initialize the first actual Point.control from the literal first entry, not the legacy default+0. Subsequent increments are single separately rounded binary64 subtraction from consecutive targets. Do not accept externally supplied redundant deltas in this first API.

Contract details/gates to freeze before compilation:

- Require supported binary64 representation (8-byte double, radix2,digits53, required normal/subnormal representation) and validated bitcast mapping. uint64 textual value->memcpy/bitcast gives the same mathematical bit pattern on supported native/Wasm layouts; this is a platform contract, not a claim about all possible C++ implementations.
- Parse integer hexadecimal without floating conversion. Enforce exact lowercase grammar/width, nonempty token/count and delimiter rules; reject whitespace,0x prefixes, signs, mixed width/case, trailing/leading/double commas and surplus values. Reject exponent bits0x7ff before any arithmetic (all NaNs/infinities), optionally before memcpy to avoid signaling-NaN floating exceptions. Initial target requires lower63bitszero; no nearzero allowance. Validate full sequence and parameter/state/settings before run, then retain the existing last-committed-prefix behavior on a later solver failure.
- Preserve both+0 and−0, minsub, minimum normal and ordinary values in bits echo. A minsub target is a valid representable loading input, although a model may have separate numerical support limits. Never silently flush/clamp an input. No claims that all finite source/model inputs numerically integrate successfully.
- Echo exact controls_bits and numeric controls, protocol/unit, settings and model/catalogue identity; omit legacy target/cycles fields because an arbitrary path has no unique amplitude/cycle count. New APIversion identifies the changed request/response. CLI controls-file is bitCSV only, with size limit and an unambiguous documented newline/file grammar. Do not accidentally pass an encodedbitCSV to old numeric parse_csv.
- Freeze generic elastic analytical inputs and source-owned MC common-control path, all5protocols, irregular/hold/reversal targets, initial−0, parser/range failures, actual failed-run prefix and same-instance recovery. Check controls_bits/pointcontrolbits exactly; verify each passed increment against exact rational RN subtraction. Keep old9-model API/default/finite-path outputs and descriptor objects byte/field identical under the optional pointer's null path. Complete malformed-input and negative corruption probes first. Builds remain coordinator-only and serial.

No algorithm/settings/controller stopping tolerances are changed by this foundation. The old schema0.1 exports lack waveform identity, so they must retain their old semantics; catalogue_hash and integration_settings alone cannot identify a caller waveform. A later deterministic producer needs its own identity/inputs/bitsequence provenance and a new source/backend regression study. It must not retrofit the old sine stream or replace its failed parity result.
