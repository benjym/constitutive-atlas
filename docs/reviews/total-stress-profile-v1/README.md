# Generic total-Cauchy incremental profile design, v1

Status: source audit and prospective implementation plan only. No shared code changes, model evaluation, backend execution or admission. The named motivating law remains the BK2022v1 associated perfect-plastic total-stress law plus separately project-derived BE projection. Its strict source-ideal initial yield policy and eventual rounded-input numerical policy remain separate; this design introduces no new numerical tolerance.

## Decision

Support incremental state-bound Cauchy stress with explicit scope `effective` **or** `total`, while retaining every other current profile restriction. Carry that scope into generated native metadata and new scope-aware laboratory/recorded result contracts. Expose absent pore pressure as JSON `null` with an availability/reason descriptor. Keep old effective-only public wrappers and serializers unchanged for old effective models; reject total models in those legacy wrappers before integration. Use the shared mechanical controllers through distinctly versioned scope-aware wrappers. Do not infer drainage, pore pressure, effective stress or a soil interpretation from a total-stress tensor.

The smallest safe first browser policy is to permit mechanical plots for total models with correct labels and complete examples, but disable normalized experiment matching and paired overlays for them. Retain the experiment/source viewer. Source-supported per-channel total-model comparisons can follow as a separate contract; they are not required to unblock research execution. Thus no historical experiment/schema migration is necessary in this first implementation.

## Audited findings

`source-map.json` contains pinned paths and review anchors.

- `atlas/model.py` requires the incremental stress dict to equal effective Cauchy sigma. The schema already allows total. `docs/FORMULATION_CONTRACT.md` also states the narrower implemented rule, so documentation must change with implementation. Legacy v0.1 migration correctly forbids assigning total and must stay unchanged.
- `atlas/compiler.py` preserves complete canonical records in describe/models JSON, so scope is already present there. Its generated native `Model` has only physical-time/axisymmetric/stress-offset metadata and no scope. The existing `stress_offset` is an **observable** offset, not a state offset: do not reinterpret it for incremental sigma. Incremental consumers require first sigma6 and use state indices0..5.
- `cpp/include/atlas/solver.hpp` controls first six stresses with no scope distinction; these mechanical equations need no reinterpretation. `Point.pore_pressure` defaults0; protocols2/3 assign initial radial stress minus current radial stress regardless of declared scope. `cpp/main.cpp` emits u for every point, and its laboratory serializer has no stress-scope metadata.
- Recorded replay computes absolute projections of state sigma or strain. It has no pore reconstruction, so the mathematical controller is scope-neutral. Its API/envelope and request must identify the stress being controlled. `web/recorded-view.mjs` CSV nevertheless hardcodes `effective_stress_*`; the HTML section title is also effective-only.
- `web/state-contract.mjs` currently rejects total examples. Laboratory controls, chart axes, pore caption and CSV/export in `web/app.js`/`index.html` assume effective stress. `web/numerics.mjs` calls the legacy API and checks settings, not stress meaning.
- `atlas/experiment_replay.py` checks incremental/stress-first shape but then unconditionally reconstructs an initial sigma from measured effective p/q. It lacks a scope check. `web/experiments.mjs` compares only protocol/loading and channel presence, not model stress scope. Browser experiment matching similarly loads effective initial stress into model state. Both require explicit guards before admitting a total model.
- Physical-time models already can declare total/effective observable stress and their schedule/time consumers return observables without pore reconstruction. This task should not change that execution profile or infer state stress from `stress_offset`. Shared metadata should represent their declared scope too; existing time/schedule result versions stay unchanged until separately revised if consumers require explicit metadata there.

## Proposed implementation sequence

1. Add a small shared Python accessor resolving declared stress binding/scope. For supported legacy incremental v0.1 only, resolve effective by its documented legacy contract; do not guess v0.2/v0.3 scope. In v0.3 incremental validation allow exactly state/sigma/cauchy with scope in effective,total; preserve persistence, Pa/sym/spatial semantics, stress-first layout, sign/kinematics/frame and all other checks. Do not migrate old model records or change scientific status.
2. Generate a distinct native enum `StressScope { none, effective, total }` in `Model`, filled from the resolved binding. Preserve `stress_offset` semantics and canonical model hashes; no inferred pore-pressure capability. The existing catalogue format already carries formulation, so changing its outer version is unnecessary. Regenerate and rebuild consumers together under parent control; positional Model initializers in synthetic fixtures must be updated explicitly.
3. Add a scope-aware laboratory serializer and entry points using the existing controller implementation: proposed names `atlas_run_scope_with_settings`, `atlas_run_controls_scope_with_settings`. Native CLI selection: `--response-contract stress-scope-0.1`, default legacy. New response `api_version=experimental-laboratory-scope-0.1`; retain numeric controls/bits/settings echo in its explicit-control variant. Keep legacy atlas_run, atlas_run_with_settings and atlas_run_controls_with_settings response/arithmetic on effective models; reject total models with a clear contract error before material calls. Pure evaluate/integrate/linearization state-array interfaces are scope-neutral and may work for total models after validation; their catalogue/model identity determines interpretation, and they must not invent u.
4. Add a parallel scope-aware recorded entry-point pair (with/without restarts), sharing all controller/restart arithmetic. Proposed request version `experimental-recorded-run-0.2`, required `stress_scope` matching resolved model metadata; path remains `experimental-recorded-path-0.1` because coefficients and targets are unchanged. Response `experimental-recorded-replay-0.2` includes the binding descriptor. Legacy recorded0.1 wrappers remain effective-only, with unchanged effective outputs. Extend Python/JS validators, adapters and native CLI selection explicitly; do not allow an optional unvalidated extra field under a closed old request.
5. Implement browser scope helper using canonical model records, validate the returned descriptor against model and catalogue hash, and select the new APIs for new scope-aware requests. Update complete-example validation, labels, protocols, charts, CSV/JSON import/export and worker adapters together. A total run must never fall back to the old engine if the new entrypoint is absent. The existing catalogue/model hash protects identity but does not alone prove engine support for this result contract.
6. Add unconditional effective-scope guard to the current drained experiment adapter and browser initial-state matching. Add model-scope gating to paired plots, including cached catalogue comparison eligibility. Keep original source data/links visible; do not rewrite effective channels as total. New total-model comparison support is deferred, not silently activated from equal units or q invariance.

## Result descriptor and u policy

The new laboratory response includes a closed descriptor such as:

```
"stress": {"source":"state","name":"sigma","measure":"cauchy",
           "scope":"total","tensor_representation":"mandel",
           "sign":"compression_positive"},
"pore_pressure": {"quantity":"change","availability":"unavailable",
                  "reason":"total_stress_without_pore_pressure_law"}
```

Each point has `u:null` when unavailable, including the initial point. Do not emit NaN, zero, an empty object or omit u ambiguously. A scoped C++ representation can retain a numeric value plus an explicit availability flag; unavailable numeric storage must never reach serialization, calculations or charts. The legacy Point/arithmetic can remain untouched if the new serializer masks it by an explicit policy, but it is preferable not to calculate a meaningless total-stress reconstruction in a new path. A shared policy function can control assignment without changing effective arithmetic.

For effective models and mechanical zero-volume protocols2/3, retain exactly the current reconstructed **change** `u=initial_radial_effective-current_radial_effective`, with availability `reconstructed` and assumption `fixed_radial_total_stress_incompressible_fluid_and_grains`. Initial u=0 is meaningful under this change convention. This is an external boundary/mixture assumption, not a model pore law. For effective protocols0/1/4, the new contract emits null/reason `not_reconstructed_for_protocol`; the legacy contract keeps its existing numeric0. No new absolute initial pore pressure or total-stress conversion is introduced.

For total scope all five controllers remain mechanical: protocol0 one-dimensional strain,1 constant radial total stress,2 zero volumetric strain,3 prescribed signed q change with zero volumetric strain,4 isotropic strain. Use these labels rather than drained/undrained claims. For effective scope preserve existing labels and describe the reconstruction assumption. Total stress q can be plotted as its own invariant, but no pore pressure, effective p′, drainage classification or experimental equivalence follows. Perfect-plastic control singularity/failure remains an honest numerical result; no new stabilization or tolerance is part of this design.

## Browser and export details

- Label initial radial stress and p axis by scope: effective stress/p′ versus total stress/p. Change title, SVG aria-label, slider aria-label, tooltip, imported-run summary and recorded stress section title together.
- Draw pore curves only when the descriptor says reconstructed and each u is a finite number; JavaScript `null/1000` equals0, so checking numeric type is essential. Show the unavailability reason on the empty panel. Do not infer availability solely from protocol2/3.
- New laboratory JSON export uses a new envelope e.g. `atlas-laboratory-export-0.2`; new recorded export `experimental-recorded-replay-export-0.2`. Include contract/specification/scope and verify on import against catalogue and engine response. Legacy import0.1 remains accepted only for effective models with the historical semantics. Stale scope is an error, not an instruction to relabel the current model.
- New CSV headers use `effective_mean_stress_Pa` or `total_mean_stress_Pa` and analogous recorded component names; include a `stress_scope` column and a `pore_pressure_availability` column. Name numerical u `pore_pressure_change_Pa`, blank when unavailable; never a numeric0 placeholder. Existing old exporters can remain for legacy exports if their effective-only restriction is enforced. All persistent state (including ep) stays in JSON; CSV stress plots do not replace restart state.
- Keep normalized experiment overlays and initial-state matching disabled for total models, with a concise explanation. The native source-measurement panel remains usable. Existing data records do not universally declare p scope explicitly: Wichtmann normalization explicitly constructs effective initial stress, but absent scope in arbitrary records must not be treated as total. A future experimental format should annotate per-channel quantity/scope and replay mapping with source receipts before enabling total comparisons.

## Compatibility and bounds

This is a new executable capability within existing model schema0.3, not schema0.4 or a migration of effective records. New result/request versions are needed because nullability, stress meaning and availability differ from old0.1 assumptions. Numerical settings, strain coordinate, state ordering, serialization precision, control tolerances and old effective calculations stay unchanged. Do not change historical evidence/reference envelopes to add metadata retroactively. Keep raw prior bytes and compare new observations under a separately frozen study.

No additional constitutive input, pore pressure state, initial yield tolerance, pressure positivity, model-specific name branch or Tresca kernel is justified. The total law's source and rounded-Mandel/reference/admission gates remain open. This packet establishes a source-path design, not implementation correctness.
