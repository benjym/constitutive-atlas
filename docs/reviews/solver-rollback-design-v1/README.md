# Prospective solver transaction corpus design

Task DESIGN-solver-rollback-corpus. Source-only proposal, 2026-10-31. Seven synthetic model definitions, eleven consuming API rows and three low-level preparation witnesses. No compiled results exist. These fixtures are engine conformance specifications, not constitutive models or admission evidence.

The probe calls actual atlas::integrate(), atlas::integrate_time(), and atlas::run_schedule(). It includes atlas/schedule.hpp, thereby using production solver/time code and generated models.hpp. It does not replace solver algorithms or install handwritten model kernels. Model indices are resolved by unique IDs. All model sources explicitly identify synthetic origin.

## Decisive assertions and API limits

- Late reset guard and late reset value failures occur after an earlier assignment changes x from2 to11. Actual consuming integrate() must return original sigma,x=2,y=5. Low-level prepare_model_increment() scratch is deliberately mutable on false: guard failure retains x11,y5; failed value checks only the first successful x write, leaving y unspecified. Separate reset success swaps x/y from the same parent state, giving x5,y2. It must not yield sequential scratch reads x5,y5.
- Runtime parameter M has valid finite bounds including DBL_MAX. Defaults M1 make every scale schema-valid; M=DBL_MAX makes exact trace(M,M,M) overflow. The trace is selected inside a predicate with otherwise finite equal arms, requiring sticky evaluation failure. No literal infinite wire values, log/exp overflow, or unbounded arithmetic is involved.
- Invalid state scales are checked through both legacy integrate() and timed integrate_time(). Invalid observable scales are checked through run_schedule(), the API which actually consumes them. integrate_time() does not consume observable scales; do not assert that it does. All failed scale vectors must be wholly nonfinite, including otherwise valid later components.
- Physical-time constant ODE d(sigma)/dt=I Pa/s, dx/dt=dy/dt=0 starts at clock2 with state(2,3,4,0,0,0,2,5). The time-dependent domain is safe through t2.5 and evaluates an invalid checked trace above t2.5 only when M=DBL_MAX. Maximum step .25 forces two accepted quarter intervals (four internal substeps), so a later failure occurs after actual positive progress. Top-level timed result must retain original state and clock2. M1 success under identical settings reaches clock3 and state(3,4,5,0,0,0,2,5) with eight internal substeps.
- Legacy settings max_depth0/max_substeps2/max_iterations3/max_backtracks0 are bounded; success controls solve unchanged residuals immediately. Timed settings minimum_step1/32, maximum_step1/4, maximum_depth4, maximum_substeps32 bound deliberate late failure. A completed child interval updates only scratch. Exact substep expectations derive from the current inspected source, not observed compiled results.
- Schedule rejection happens before any initial point is appended, so empty points are correct; there is no returned original state/time field. Success uses one all-strain-hold segment of duration1 and one sample, resulting in three points (initial, transition, sample). The endpoint remains governed by the same constant ODE. Schedule state/time comparisons refer to the last point.
- Source arguments state, parameters and loading must remain bitwise unchanged in all calls. Derived scratch and diagnostics are not promised transactional. This probe covers doubles in consuming solvers; previous Jet expression audit remains separate. It does not establish history-program transaction semantics, nonlinear stress-control convergence, user constitutive admission, or experimental agreement.
