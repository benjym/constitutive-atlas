# Required pre-install package software controls

These are prospective controls, not observed passes. Run the exact v4 complete bundle functions against isolated source/build copies; do not execute any binary. Set their ROOT only to the isolated copy. Supply exact existing scientific approval/interface records and supporting files so positive controls exercise the real inherited guards. Preserve source and artifact receipts before/after each test. Failed package output must never be treated as publishable merely because partial files exist.

1. Positive Maxwell and current NorSand: exact accepted source plus only the notice delta, generated files, verified artifacts and the supplied build-local records succeed. Rehash every output against its manifest. Check module/Wasm bytes, qualification bytes and accepted build-review bytes match the corresponding captured inputs. Confirm qualification's `build-review.json` link resolves locally and its hash matches. Confirm all three scientific model/approval identities remain unchanged. Verify standard package NOTICES bytes match the accepted notice pin.
2. Source closure: independently modify one byte in scalar `pow.c`, `libm.h`, COPYRIGHT, NOTICES, common helper, tensor/solver headers, nested `numerics/symmetric_spectral.hpp`, compiler Python, schema, target CMake, exact model and synthetic fixture. Each must reject without changing any receipt. Add/remove an extra `.hpp`, scalar file or compiler/schema file and require exact-set rejection. Maxwell/NorSand generated output changes must separately reject, including `path_api.cpp`/`path_models.hpp` changes that leave catalogue JSON unchanged.
3. Artifacts: independently mutate module and Wasm bytes, exchange the one-definition linkage-only NorSand build for the qualified three-definition build, or exchange another model's consumer artifact. Require rejection against unchanged qualification. Preserve exact failures. A native artifact change also invalidates the underlying numerical evidence even though these web guards consume Wasm; do not self-repin its source qualification.
4. Qualification and review: missing, failed, malformed or stale qualification/review; wrong model/schema; changed gate bool/count; wrong source manifest/reference hash; absent source binding; missing/extra source key; changed accepted binding; changed reviewer hash or file; failed review status; identical implementation/reviewer ID; whitespace-only or non-string ID. Every applicable guard must reject. NorSand must reject noncanonical, absolute, traversal or symlink-escaping review paths. Maxwell must retain its existing safe-relative-path rules.
5. Independent-review semantics: mutate qualification to point to different accepted bytes without updating the review hash, and mutate accepted binding while retaining the original qualification. Both reject. Do not call a synthetic test receipt an independent scientific decision; use controlled mutations of copied real records solely as negative software inputs.
6. Capture/late drift: arrange a test-only hook after artifact bytes are captured, then change build module/Wasm files. The resulting successful new-branch package must contain the originally captured qualified bytes, never the changed bytes. Separately change a source file after the initial guard and before the final recheck; require failure. Preserve the failed output and exit record. Do not monkeypatch guards to force success.
7. Historical fallback: absence of current NorSand receipt exercises the unchanged old branch with the exact retained historical source/artifacts and succeeds; historical source/artifact mutation rejects. Current common-runtime source plus no current receipt must reject under the old source guard. A malformed present current receipt must reject rather than fall back to old qualification.
8. Distribution and preservation: standard builder copies the exact accepted NOTICES; missing/changed source notice blocks a complete successful current package. Old receipts, source freezes, previous package manifests and failed tests remain byte-identical. Verify all changed installation bases against proposal freeze immediately before mutation; preserve a stopped-drift result. No shared installation, numerical rerun, E6/E7 acceptance or remote release is implied by successful software controls.
