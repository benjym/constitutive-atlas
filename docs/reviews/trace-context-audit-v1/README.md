# Independent trace/dev generated-context protocol audit

Task: AUDIT-trace-context-protocol. Reviewer: trace_context_audit, 2026-10-31. Source-only bounded review; no shared edits, builds, compiled execution or scientific admission.

The proposed repair is appropriate if it couples Python exact-input trace to sticky material evaluation flags, while preserving the already tested tensor operator bytes. Put material wrappers in a new checked_trace.hpp, include it in generated models, and leave tensor.hpp and the original operator study unchanged. History already checks every executed AST subtree through hcheck and therefore needs actual execution verification, not a second material flag mechanism.

## Findings and implementation conditions

1. **Scale compilation blocker found before integration.** Existing validation accepts trace/dev in parameter-only scales. Material cpp emission will add atlas_eval_ok, but both generated scale functions currently lack that local variable. The coordinator's proposed repair is sound: declare a fresh flag per call, evaluate the complete scale vector, and replace all entries with quiet NaN on any selected checked-operation rejection; existing solver boundaries reject nonfinite/nonpositive scales. Do not throw, silently retain finite fallback values, or ban previously valid scale expressions. Use trace(sym(K,K,K,0*K,0*K,0*K))/3 as the valid fixture; scale symbols exclude I, so the initially suggested trace(K*I)/3 example was not valid. Include state and observable scales, masked failure, finite trace, lazy arms and dev-result overflow. On flag rejection, assert the complete vector is invalidated even if earlier entries were valid. Low-level scale routines return sentinel values; solver failure is a separate assertion.

2. **Sticky failure is essential.** trace_or_mark and dev_or_mark must only change true to false; returning a finite placeholder must never turn a selected invalid trace in a predicate into an accepted model. Use both select(trace(A)>0,1,2) and 0*trace(A). Include selected invalid child followed by a valid sibling/call, then a completely separate successful evaluate call to establish per-call reset without accidental intra-call recovery.

3. **dev has an independent final-result gate.** With M=DBL_MAX, A=(M,-M,-M,0,0,0) has finite trace -M but its first deviator component overflows. Check full result finiteness, including all 38 Jet derivatives. A finite primal with that triple in a derivative column must reject. This is different from trace final overflow. No correctly rounded dev or exact zero trace(dev(A)) claim follows: subtraction and division remain ordinary arithmetic.

4. **Full input validation survives masking.** trace currently validates all six primals and every seed in all six components, including offdiagonal seeds that contribute zero to trace. Check NaN and both infinities per component/column and failure recovery. A valid derivative triple whose exact sum overflows must reject even though the primal is finite and the expression ultimately becomes a boolean. Good inputs with large intermediate sum but finite final sum must pass. Scalar-only tests cannot establish this.

5. **Direct output is scratch, committed state is transactional.** evaluate_model resizes/writes out before its final status return. prepare_model_increment starts out=zn and can write an earlier reset before a later guard/value fails. Neither low-level API currently promises output nonmutation on false. Preserve caller z/zn/loading/parameters and assert false; do not require unchanged scratch out unless deliberately extending the API. integrate returns the original state on failure; integrate_time_history additionally retains the original clock. History run_N returns original values/generation/epoch and clears events on failure. Diagnostics such as attempted/executed/failed phase intentionally remain informative.

6. **Generated history has stronger subtree checks already.** history_compiler._expression wraps every executed trace/dev child in hcheck before a containing comparison, arithmetic operation or select. Invalid finite-input trace/dev therefore throws before a predicate can mask it. Conditional arms stay lazy. run_N catches arithmetic failures inside the transaction after input validation; malformed nonfinite wire input can throw before Result exists and is a separate API contract. Test finite wire input leading to arithmetic failure to assess rollback.

7. **Do not conflate contexts or execution modes.** Derived fields are eager and checked even when unused. Initial checks execute only when check_initial is true. check_only returns before equations/observables; observables_only evaluates observables and skips equations. Add witnesses proving these actual paths and the corresponding lazy skipped invalid work. A regenerated header or counted source substring proves neither runtime control flow nor transaction semantics.

## Proposed bounded decisive corpus

Freeze exact model/program bytes, generated headers, probe sources, expected rows, toolchain settings and policy before either backend is observed. Use explicit IDs; compare full ordered unique rows, not only aggregate check counts. The same independently frozen expected semantics applies to native and Wasm. Report every mismatch and retain failed runs.
