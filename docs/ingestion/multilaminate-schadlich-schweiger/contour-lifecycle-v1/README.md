## Selected proposal and source conflicts

Name the finite lifecycle profile `atlas-corrected-four-contour-parent-v1`. Use it only within the incomplete **corrected Atlas** identity; no journal/original implementation equivalence is asserted. The intended future full law retains all its other terms and open gates.

Chapter4 p62 describes reversal detection and reactivation throughout loading histories. AppendixD p210 additionally gates contour creation by `iStep<=1`. The earlier host reconciliation establishes that this is a host phase step, not the stiffness-pass counter. An identical geometric path 0→8→4 therefore creates a second contour at host step1 but not step10 under that gate. The proposed corrected identity **removes this phase-step gate**. This is an explicit model/algorithm choice motivated by the chapter's general history rule, not an algebraic correction compelled by the source, and not permission to reinterpret iStep. A reviewer must accept the departure before integration.

Additional explicit choices: a rounded-zero local increment returns the exact committed contour state, preventing boundary-tie erasure on a hold; all three local coordinates are retained despite the printed `Star` assignment; every outer stiffness pass derives its entire candidate history from the same committed parent snapshot. These choices establish Atlas behavior; they do not prove the listing implemented it. Source thresholds `abs(dx_j)<1e-12` and positive-distance/radius guards `>1e-15` are retained, without tuning against backend results.

## Complete finite event contract

The local coordinates are the source triple `(epsilon_nd,gamma_s,gamma_t)` and are dimensionless. Their Euclidean metric is the source Eq111 metric, not automatically a global Mandel norm. The contract does not resolve the earlier local work-conjugacy/projection or sign conversion gates.

Persistent contour memory per plane is x[3], common active return anchor[3], degradation distance gamma, and an ordered outer-to-inner list of 1–4 `(center[3],radius)` records. The active record is the last. Initial state is x=anchor=0, gamma=0 and one origin-centered zero-radius primary contour. This is virgin contour preparation only; it does not initialize cap/cone/prestress/damage or permit erasing an imported non-virgin history. Unused capacity is not material memory and must have a canonical serialization.

1. Read the immutable committed parent's complete state. Validate finite triples, nonnegative finite radii/distance, count1–4, primary center0 and endpoint/gamma consistency. Round each small local parent-total increment component using the source threshold, then form endpoint x. A zero rounded increment is an exact hold/no-op.
2. Check outer contours in order, excluding the active one. The first with endpoint distance d>=stored radius and d>1e-15 wins. Erase all inner records. Keep the selected center; set its radius and gamma to d. For a secondary contour set anchor=2*center-x; for the primary set anchor=0. Stop this event evaluation. Thus simultaneous outer ties select the outermost reached contour.
3. Otherwise evaluate distance d to the active center. If d>=radius and d>1e-15, keep the primary center fixed; for a secondary contour set center=(x+anchor)/2. Recompute d, store radius=d and gamma=d. Equality enters this growth branch; it does not create a reversal.
4. Otherwise, if d<radius, radius>1e-15, creation is permitted and count<4, append one active contour. Set anchor to the previous committed endpoint, center=(x+anchor)/2 and radius=gamma=norm(x-center). This is one endpoint event, not arbitrary repeated creation in a single increment.
5. At depth4 do **not** create a fifth contour, roll the oldest record or merge histories. Preserve all centers/radii and anchor, set gamma to the distance to the active center, and report `depth-saturated`. This selects the appendix's bounded-history behavior explicitly, rather than implying unlimited nested resolution. Later outer crossings can free slots for arbitrarily many sequential cycles.
6. If no event applies, preserve contour memory/anchor and set gamma=d. The external `creation_permitted` Boolean is an explicit input; it is not inferred from a phase index. This packet only settles geometry and transaction semantics. The full critical-state/failure inhibition and stiffness-recovery composition remain TIME-02, including the source discrepancy that failure disables creation while outer erasure is still executed.

This is an **endpoint** event rule. A supplied path that turns and returns between endpoints requires separate parent path segments; no hidden reversal reconstruction occurs. Material internal substeps contribute to a single parent-total local strain endpoint. They do not each commit contour events. Arbitrary subdivision may change the endpoint algorithm, and this packet claims neither subdivision invariance nor full Masing response or convergence. A failure that cuts back one parent into accepted smaller parents changes the discretization and must be qualified as such.

## Outer iteration, failure and restart contract

For a parent increment, freeze the full all-plane/all-point committed state and the neighbor snapshot required by the full nonlocal host. Run each outer stiffness proposal from that same parent snapshot. Inner material substeps and plane return iterations are scratch and may not mutate committed contour, hardening or neighbor state. After the substep solve, evaluate contour events once from its parent-total local strain. Supply proposed degradation distances to the next coupled stiffness pass, but reevaluate the candidate histories from the original parent again. Never feed a previous outer proposal back as committed history.

A contour count alone is not a convergence test: centers/radii/distance and the assembled stiffness may change at constant count. A later generic capability must define prospective tolerances, iteration bounds and a whole-state/stiffness convergence gate. No count-only convergence or source `iterStiff<11` acceptance is adopted here. This packet does not implement the coupled stress/stiffness iteration or certify its convergence.

Commit all physical histories only after the full coupled material and multi-point acceptance gates succeed. If any local/nonlocal solve fails, reject the entire proposal; contour states and published neighbor damage remain exactly the parent snapshot. A discarded proposal has no durable file writes. Retrying the same input from that parent is deterministic. Reset to virgin history is a distinct explicit material reinitialization, never a phase-name/host-counter change or restart.

Restart must preserve profile identity, coordinate convention, all x/anchor/gamma/active records plus the full model's other physical history and prepared identity. A profile mismatch is rejected. A saved accepted snapshot resumes from that snapshot; pending scratch is discarded. Exact replay on one implementation is a separate claim from cross-toolchain floating-point equivalence. Failure restoration and all-point atomicity will need testing in the actual common engine, not just this standalone specification.
