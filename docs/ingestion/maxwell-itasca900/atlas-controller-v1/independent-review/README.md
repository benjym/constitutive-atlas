## Findings and closure

**Exact model binding.** The initially inspected loader hashed the exact model file but compared its catalogue entry only by model ID. A separate same-ID definition/descriptor could therefore accompany the approved model file. I reported this gap. The coordinator added complete catalogue model equality to `[definition]` and canonical-key descriptor equality, replaced the minimal mock descriptor with the actual model, and added a newly hashed same-ID changed-metadata rejection test before factory acquisition. I inspected the correction and reran the final tests. This is semantic exact-model binding within the served package; no cross-language JSON digest reimplementation is claimed.

**Verified Wasm consumption.** During review the coordinator identified that the historical generated module consumes `instantiateWasm` but does not read `Module.wasmBinary`. I independently inspected the generated JavaScript as text without executing it and confirmed the relevant hook path. The initial option handoff did not ensure the verified Wasm bytes were used. Final code explicitly instantiates the verified BufferSource through `WebAssembly.instantiate`, with the generated module's imports, and delivers the instance/module to its completion callback. An external failure promise races factory completion because the historical generated hook path itself supplies no rejection continuation. The loader rejects a factory that ignores the hook or completes before verified instantiation; fallback `locateFile` requests throw. Durable tests exercise byte/import handoff, asynchronous instantiation rejection, ignored hook, fallback loading and premature completion without any real compiled execution.

Initial/intermediate test logs are retained in the enclosing packet. The original 7/8 runtime result was a fake-DOM adapter failure from numeric input.value lacking browser string coercion; the adapter was corrected, not production numerical behavior. My earlier 25-group receipt log is preserved as `tests-before-wasm-hook.log`; final logs apply to the corrected loader.

## Package and runtime assessment

Controls are validated before asset acquisition. Identity requires the exact pinned Maxwell ID/hash, a catalogue identity and a nonempty revision. Every engine module, Wasm, catalogue, definition, approval, review, readable review and required interface-component request uses no-store and verifies SHA-256. All six required component names must appear exactly. Approval/review status, model hash/ID/path and review-file hash are bound; canonical review validity remains established by the repository review validator and future package builder, not a new browser scientific review. Complete model/catalogue equality precedes factory import, and embedded descriptor agreement precedes schedule calls.

The default generated engine module is imported from the verified bytes through a short-lived JavaScript Blob URL with revocation in finally. The real browser Blob import and actual generated factory are not executed in these Node tests. The mocks prove which bytes and imports reach the injectable loader boundaries and exercise the runtime checks; they do not prove native/Wasm behavior.

One worker is owned per request. Generation and worker-identity checks reject stale messages, errors and timers; prior work is terminated, timers and export state cleared on edits, deactivation and failure, and recovery remains possible. My independent probe explicitly invokes stale timeout, message and error callbacks after a newer request and after completion, and verifies no state change. It also rejects imported module/Wasm provenance changes and verifies recovery/cancellation. The 120-second timeout is a UI resource bound, not a numerical gate.

The main thread repeats complete-result and reconstructed-ABI checks. Imported runs must match the package identity returned by the worker and the entire deterministic result before export is enabled. File reads and identity fetches are fenced by the generation token and active state; a late import cannot reactivate a deselected panel. Tests cover that race and valid replay-before-export. Worker acquisition/postMessage failures clear timers and remain recoverable.

The controller's actual handlers expose all four complete source presets, parameters, initial stress/strain/rate, start time and segment histories. The full table has six stresses, six strains and six rates at every initial/event/regular point; null rates display as unresolved. Component plots carry physical-time and SI-derived unit labels. Primary source URLs, exact model/review/approval links, the trace-projector interpretation, restricted scope and lack of experimental comparison are visible. Reset restores a complete selected preset; edits clear stale plots/tables/export, and deactivation restores ordinary views. Tests use a small DOM adapter, not a browser rendering engine.
