## Prospective blockers before compiled qualification claims

1. Exact grid integrity: main checker verifies count and named checkpoints but not every point against its planned coordinate; parity-v1 verifies coordinate equality between backends rather than equality to the request plan. Require every returned point's coordinate to equal the corresponding frozen grid value, including noncheckpoint points. Both reports can otherwise agree on incorrect grids.
2. Replay receipt integrity and timing: main checker tests only presence of restart_receipt. Require exact index and complete finite13entry state, matching the continuous parent at that restart boundary and replay state at that boundary. Runner restarts **before update256, after accepted update255**; execution-v1 policy says after index256. Preserve the v1 policy and prospectively document the corrected boundary before observations.
3. AD branch-monitoring claim: current code checks gamma>1e-10 and constant API branch_policy='selected_fixed'. That label describes the AD contract; it does not prove FD roots retain the same candidate branches. Check actual relevant branch predicates/margins for base and FD converged states: nonzero relative direction, psi, b:n absolute-value branch, loose-state D_raw branch when active, and smooth complementarity radius. Verify positive pressure and strict b_ref distance. Require nonempty finite positive accepted partition fractions summing to1, as well as equality; matching empty/malformed lists currently pass the list/equality test. If evidence must cover multiple internal roots, returned final state alone cannot establish all intermediate branch selections; the qualification scope must reflect available diagnostics or explicitly gate a single accepted substep.
