## Blocking assessor/collector corrections

1. **Bind the transport exception precisely.** The request currently permits transport rejection for exactly `finite-404`, the pure Mandel shear minimum subnormal `0x0.0000000000001p-1022`. The assessor accepts any failed response for that case. That would also excuse a solver/domain/model failure. Require the exact frozen case/component bits, a specifically identified CSV numeric-conversion failure, and no claimed successful state. A successful response must still pass the ordinary source gate; a zero-stress hold cannot pass. The native `std::stod` implementation may reject this decimal underflow, so a narrow transport exception is reasonable. Keep the exception separate from numerical qualification of the core target already passed in Python.
2. **Assert complete path identity before zip.** `assess` compares `zip(req['paths'],raw['paths'])` without asserting exact count/IDs first. A raw study truncated after three refinement paths can potentially pass its ratios and finest-error criterion while claiming the four-path propagated step count. Require exact ordered IDs and all four path lengths. Apply ordered identity assertions to negatives as well, rather than only their count.
3. **Use frozen request fields for actual calls.** The native collector uses hardcoded MODEL/PARAMS/SETTINGS while the Wasm collector reads the request. Current values agree, but the request hash does not guarantee executed controls if these fields change. Read model/parameters/settings from req, allow explicitly declared per-case values, and check echoed model/settings/parameters/control/state where available. Bind raw results to the exact request and actual artifacts; the Wasm loader hash alone does not pin its external `.wasm` binary.
4. **Enforce exact holds.** Repeated parsed output equality establishes repeatability, not exact state identity. The finite comparison is tolerance based, so a deterministic hold drift below budget would pass. For every stored all-zero increment, assert returned full state equals incoming state exactly, in addition to repeated response checks. The source contract and prospective policy explicitly require this.

These are static source findings, not observed compiled failures. Preserve this plan identity and create a revised identity when correcting it.
