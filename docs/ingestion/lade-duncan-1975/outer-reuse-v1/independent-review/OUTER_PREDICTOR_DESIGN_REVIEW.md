# Source-only prior-increment predictor assessment

Decision: defensible as a separately identified generic numerical initialization study, with the conditions below. This is not approval of an implementation, new numerical results, admission or E5. The current source inspected is the frozen outer-reuse solver; it initializes protocol-1 lateral increment to −.2 times axial increment at every point, evaluates a new constitutive trajectory from the committed parent for every outer trial, and uses up to 30 outer iterations. Saved internal-cost evidence showed seven integrations per completed dense step in the measured long prefix. An evolving lateral predictor directly targets that repeated outer work. Neither the saved timeout nor this rationale proves that it will improve runtime.

For a smooth regular drained trajectory, the previous accepted incremental lateral/axial ratio is a consistent local secant approximation to the next ratio; constant-step continuation usually makes its initial control residual smaller. This assumes a regular local branch. Yield activation, unloading, reversal and constitutive/domain singularities can invalidate it. It is not an analytical Lade–Duncan law or a new tangent. The midpoint elastic/source lifetime argument still concerns each accepted integration; it supplies no convergence proof for the outer initial guess.

Required scope and guards:

- Apply only to the explicitly opted-in non-rate residual protocol-1 run path. Preserve six-setting legacy behavior, protocol 3 and all other protocols. Keep predictor state local to one run, never static/thread-local/global, and reset it at run entry.
- Store the exact actual six-component `de` returned by a successful controlled step only after the caller commits its resulting point. Do not recover it by subtracting cumulative rounded strain, or from a rejected line search, cached transaction, perturbed trial or partially failed step.
- Require all six previous components and the new axial increment finite, exact axisymmetric lateral components with zero shears under an explicitly specified check, nonzero previous/current axial components and the same sign. Prefer sign comparison rather than a product that can overflow or underflow. Check the ratio and final scaled lateral guess for finiteness. First step, zero hold, reversal and guard failure use cold initialization; clear eligibility after holds/reversals so stale direction memory is not silently reused. Tiny unequal step ratios require explicit underflow/overflow cases in tests.
- Predict only the lateral increment, leave prescribed axial loading and all shears unchanged, and use the actual current committed `zn`, parameters and settings in every integrate. No prior endpoint/root/history is a substitute for the new solve. No projection, pressure floor, altered source residual or changed acceptance tolerance follows from the guess.
- Keep the existing 30-iteration, 11 line-search trials, implicit/substep/depth/work and 120-second bounds. No later failed perturbed trial or unsuccessful line search receives a new recovery opportunity.

The proposed initial-material-trial fallback is reasonable but optional, and must be frozen explicitly. If the warm first trial fails, iteration 0 is spent and iteration 1 starts at the original cold lateral guess, without committing anything from the failed trial. The failed call must be counted and consume ordinary applicable resources. This gives at most 29 remaining cold outer iterations, not a renewed 30. It is not equivalent to prior cold behavior: a path needing all 30 cold iterations may now fail. Without fallback, an inadmissible warm initial trial can lose a previously successful path immediately. Neither variant dominates mathematically. Avoid eagerly evaluating warm and cold alternatives, adding an initial screening solve, or retrying a later failure under a new budget. Under the current loop, at most 30×(1+1+11)=390 actual integrations per step remains a conservative ceiling; cache hits lower actual calls. Test actual counters and exact rollback for the fallback branch rather than relying only on this bound.

Necessary prospective evidence before any performance claim:

1. A pure/controller fixture covers first/nonuniform same-sign steps, both directions, hold/reversal clearing, signed zero, tiny/overflow ratios, malformed prior de, per-run reset, failed warm-first/cold-next transition, iteration exhaustion, exact retained parent and unchanged disabled/protocol/rate paths. Verify actual caller commit order and all six prescribed components. Exercise an admissible but poor warm guess as well as a failed one; no automatic improvement is assumed.
2. Cache on/off strict full-response fidelity compares runs using the SAME new predictor and the SAME fallback policy. Cache ownership, full bitwise key, one-use lifecycle and complete Advance diagnostics stay unchanged. Comparing new-predictor output to old cold output cannot prove cache identity.
3. Separately compare the previous qualified runtime and new runtime on frozen smooth, cyclic, nonuniform, hold/reversal, tiny/domain and invalid paths. Disclose changed iterations, substep meshes, diagnostics, success/failure and physical state errors. Bitwise old/new trajectory identity is not required for a genuinely changed initial guess; independent source error, refinement and domain/rollback gates remain required. A changed success cannot be silently classed as a diagnostic-only difference.
4. Freeze an initial bounded work comparison (outer iterations and actual integrations, including failed warm admission) on representative existing paths before reattempting the exact hardcase. Show measured work reduction rather than another unsupported bottleneck claim. No success is guaranteed by the source analysis. Then use the identical native and fresh-worker Wasm hardcase cap, module-init included, and the full original source/refinement/domain/lifecycle/legacy/own-parent-chain/parity campaigns. Preserve all prior failures; no reduced matrix, relaxed trend, new deadline or special dense-path formula.

The exact model JSON and original source can remain unchanged, but the runtime/study identity and receipts must be new. An implementation must receive a separate exact-byte prospective review. The smallest next action is to freeze this narrow predictor/fallback contract and targeted work/rollback fixtures; no scientific qualification is granted today.
