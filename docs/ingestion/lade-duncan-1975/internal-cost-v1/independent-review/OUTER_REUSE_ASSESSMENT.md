## Source opportunity and equivalence boundary

In controlled_step protocol1 a successful line-search test calls integrate(model,actual zn,testde,p,settings), accepts strict lateral-residual decrease, updates lateral, then repeats the top-of-outer-loop integration at the resulting de. Protocol3 has the analogous da/de update and deviator-residual test. The successful test has already completed the SAME entire constitutive transaction that the following trial requests, provided reconstructed de and every integration input are bitwise identical. Reusing that complete Advance once is stronger than reusing an implicit root: the previous result already contains accepted two-half substeps, history, domain/error checks, exact transaction state, settings/message and diagnostics. No different parent/loading may use it.

The current code mathematically constructs matching de, but floating-point expression contraction or signed zeros can make mathematically equal reconstructions differ. Therefore do not rely on algebraic equality, tolerance, vector operator== or a stress-only key. Check bitwise identity of all6decomponents before reuse, or explicitly feed the exact selected testde into the next iteration while separately proving that change does not alter the original arithmetic trajectory. A mismatch must invoke the original integrate call; the conservative bitwise guard is simpler to review.

Key/provenance includes exact model identity, complete immutable parent state (including signed history carrier/transients), complete parameter vector and every IntegrationSettings field. Within one controlled_step call these are already const and fixed; storing a local record with that scope plus exact candidate de makes the proof straightforward. If a helper is reusable beyond that scope, store/copy the full key and compare every component/kind/bit. No tolerance-based lookup, global cache, cross-request use, stale settings, changed model/profile, different time/history, or approximate strain match is permitted. Generic determinism and stable floating rounding mode are preconditions; do not extend to nondeterministic/stateful kernels without review.

## Transaction and algorithm guards

Retain only an ok=true, complete successful line-search Advance after its strict improvement test. Failed or merely perturbed tangent evaluations are never reusable. No partially completed solve, failed macro state, pre-check-only candidate, or state-only payload enters the slot. Cache ownership must be by value (or safely moved after all current use); parent/input/next output must not alias it. Consume/reset the slot at exactly the following outer trial, even on mismatch. Scope the slot to the current controlled_step invocation and protocol1/3; destroy it on return/failure. Keep original outer30iteration/backtrack/correction/control-residual bounds and tests unchanged.

On hit, use the WHOLE prior Advance as the next trial, then execute the same outer convergence test/derivative/correction logic. Do not directly declare outer convergence at the line-search site or skip the next outer iteration. No additional solve budget, retries, altered Newton/tangent behavior or domain/error-gate waiver is introduced. Under exact input identity, skipping a duplicate deterministic integration preserves the logical result and accepted trajectory. No root under different history is reused. Per-integration reservations/iterations remain those of the successful transaction; the cached result has already consumed that real work once.

Keep default/disabled/rate/unrelated protocols on their original route unless separately authorized and qualified. An explicit opt-in or separately identified isolated runtime is needed. For generic rate profiles, the integrate API's complete history/time contract must be included; this source opportunity is bounded to the reviewed residual-law opt-in path. Do not silently broaden it merely because controlled_step is generic.
