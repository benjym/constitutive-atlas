## Smallest safe durable retention proposal

Retain the failed tree and guard copies until successful v2 package/browser qualification and independent review, followed by a fresh coordinator consumer check for these exact paths. A missing current browser result is not grounds to discard failed package evidence. The inventory preserves exact file bytes by SHA-256, relative names, directory entries, POSIX modes and nanosecond mtimes. It does not preserve inode identity, APFS clones or allocation and does not claim these are scientific evidence.

After those gates, create one losslessly compressed PAX archive of ONLY the owned site-v1 and source-guard-checks-v1 trees, retaining their two top-level names. Preserve exact bytes and modes, include empty directories, and retain this inventory as authoritative restoration metadata (nanosecond mtimes can be reapplied from it). Do not dereference links or archive any other resource; the current inventory has zero symlinks. Store the archive in a coordinator-approved durable ignored evidence location, outside the disposable temp tree, under a content-hash name. Compression ratio is unmeasured. Do not rely on rerunning builders to recreate generated failures.

Before removal, verify the stored archive against every inventory entry using `verify_recovery_archive.py` (read-only streaming, no extraction), hash the entire archive, then perform a separate isolated recovery drill that restores inventory metadata and verifies every content hash/path/mode. Save the archive hash/size, inventory hash, verifier command/result, restored-file check and durable path in a new retention receipt. Check original trees still match the frozen inventory and no process/open file/cwd uses them immediately before any coordinator removal. Use unlink-only removal without chmod/truncate; save exact action and observed free space. No removal is authorized by this packet.

A later optional content-addressed store can avoid duplicate payloads: retain every unique blob once plus this path/metadata manifest. After actual site-v2 success, identical files may reuse its immutable archived blobs only if every hash is checked and that archive has independent durable retention. Never reference mutable site-v2, another task's temp assets, unpinned source paths or inferred regenerated bytes as the sole recovery source. A whole compressed archive is the simpler lossless choice; it avoids a new cross-packet retention dependency. The 2.8 MB guard tree is cheap enough to include in full, including copied public engine assets, without copying their original other-task resources.
