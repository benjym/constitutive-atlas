# Current dependency release-hook design

Source-only proposal. This note changes no live helper, hook, workflow, default, build or artifact. Implementation requires an explicit path whitelist, independent exact source acceptance, and actual acceptance/retention of all three refreshed engines. The historical provisioner and its tests stay byte-exact.

## New pure guard

Proposed NEW `tools/check_current_dependency_assets.py`, with fixed engine paths above and required exclusive `--output NEW_REPORT_DIRECTORY`. It validates retained current assets through the existing approved bundlers; it does not provision, extract, install or overwrite assets. It must not invoke any module, native library, material runner, browser, compiler, CMake target or Node script.

1. Require all fixed inputs to be regular files/directories below the repository; reject traversal/symlink roots or descendants. Never search for an older asset or silently fall back to historical directories.
2. Snapshot current engine bytes, receipt pins, active guard/helper sources and relevant current source closures. Record actual registry/review/source-archive identities used by guards. Do not create an approval or fabricate a build acceptance.
3. Lazily invoke `build_controlled_path_web.bundle`, `build_interface2016_web.bundle`, and `build_maxwell_laboratory.bundle` in separate, exclusively task-owned temporary destinations. These functions run pure source regeneration and exact packaging validation; they do not execute compiled laws. They require canonical scientific approval, current generated bytes, source/engine binding and independent actual build acceptance. Existing read-only Git revision lookup inside the Maxwell bundler is permitted; no new shell runner is needed.
4. Hash/inspect the generated package identities/manifests and source/engine snapshots, then verify that all inputs remain byte-identical. Report explicit source/retained-asset/package-guard success only, with `compiled_calls: 0`. Do not report numerical/browser/live qualification from this guard.
5. Write receipts even on failure before deleting its own temporary package outputs. Preserve failure reason, completed guard results and before/after identities; exit nonzero on any missing/stale/malformed asset or failed guard. Refuse existing report output. Keep report references repository-relative or package-relative, without unusable temporary-directory links. Never delete or rewrite the retained engine inputs.

This reuses strong existing guards and adds no scientific gate exception. It avoids rerunning the old Bingham-bound twelve-file dependency archive through source guards that now correctly reject that historical closure. The old archive, `tools/provision_bingham_dependency_assets.py`, `tools/provision_maxwell_assets.py` and their tests remain historical evidence and regression coverage.

```sh

```

Keep the adjacent `tests.test_provision_maxwell_assets` unit test, implicit request restoration, implicit-path provisioner, Bingham/Perzyna provisioners and approved-data fetching unchanged. The old provisioner unit test uses mocked guards and exercises historical archive safety; retaining it does not install the obsolete actual engines.

```sh
python3 -B tools/check_maxwell_ci.py --build docs/ingestion/vibe-2026/maxwell-refresh-v1/execution-v1/engine --output "$RUNNER_TEMP/maxwell-ci-regression"
```

That existing command **does execute** the retained Maxwell Wasm regression and public presets. It stays a separate existing numerical CI step; the new pure guard must not call it. Do not change `check_maxwell_ci.py`, its frozen references, numerical gates or default as part of this hook patch.

The three actual `build_web.py` invocations (qualification twice, Pages once) must explicitly pass all three durable engine flags:

```sh

  --controlled-path-wasm-dir docs/ingestion/vibe-2026/controlled-path-refresh-v1/execution-v2/norsand/engine \
  --interface2016-wasm-dir docs/ingestion/vibe-2026/controlled-path-refresh-v1/execution-v2/interface2016/engine \
```

Keep the Pages `env GITHUB_SHA="$ATLAS_PUBLICATION_REVISION"` prefix and all other original command options. Update the same three defaults in `tools/build_web.py` to the durable paths, so local ordinary packaging agrees with hooks. Do not change scientific approval rules or package guards. Step display labels mentioning obsolete paths may be corrected to describe their actual command, without changing adjacent build/test commands.

Retain the new guard report and existing Maxwell regression evidence after failure. Add one `if: always()` artifact upload per qualification job for `$RUNNER_TEMP/current-dependency-guards/` and `$RUNNER_TEMP/maxwell-ci-regression/`. Extend the existing Pages `pages-package-checks` artifact paths with the guard report directory while retaining `packaged-laboratory.json` and `if: always()`. Do not alter deployment permissions, triggers, toolchain versions, target counts, build parallelism or publication authority.
