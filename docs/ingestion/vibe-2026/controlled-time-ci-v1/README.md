# Portable controlled-time CI qualification

Source preparation only. This packet adds a durable single-job native-first qualification workflow; no local build, compiled module, browser or remote CI execution was performed.

`plan-v3.json` preserves the original numerical-qualification `plan-v2.json`. Its only differences are a new identity and nine execution pin paths relocated from workstation roots to repository-relative paths. `portable-plan-proof.json` and `portable-plan.diff` identify every change. Reversing them reproduces the original bytes exactly. All source hashes, 32 point cases, eight histories, seven invalid contexts, inputs, thresholds and integrator settings remain unchanged. Historical `histories[*].reference_path` strings remain unchanged provenance; collectors read frozen embedded references and verify `source_files`, rather than opening those strings.

`prepare_portable_plan.py` is the stdlib-only exclusive-write generator. Existing outputs must never be overwritten. `tools/check_controlled_time_ci.py verify --report NEW_PATH` checks the exact accepted generic correction, collector and Stage A freezes, the executed Stage B engine against accepted Stage B v3, this CI source freeze, and every portable source pin. Inactive Stage B UI/packager files are explicitly excluded from backend closure. This does not authorize changing the frozen collectors or runtime.

The workflow uses the project's existing action/toolchain conventions and one Ubuntu job. It verifies inputs before configuring; then builds and qualifies synthetic native six groups, VIBE native 32 points/eight sampled histories, matching synthetic Wasm, and VIBE Wasm with the exact native peer and identical portable plan. Every build names one target and uses `--parallel 1`. Existing corrected corpus wrappers and unchanged model collectors retain their gates, source/artifact identities, raw buffers and diagnostics. All command pipelines use `pipefail`. Always-run byte capture and artifact upload retain logs, existing generated sources, actual engines and build metadata after failures. Actual run identifiers, compiler versions and source/artifact hashes are captured by CI; source preparation is not a passing CI result.

Pure checks: parse Python source without imports, parse workflow YAML, assert one job/four serial target builds/two always evidence steps, and run helper verification. `source-checks-v1.json` is pre-freeze source evidence; `pure-verification-v1.json` is a post-freeze receipt excluded from the source manifest to avoid a hash cycle. No temporary build trees or background processes were created. Remaining action: independent source review, then coordinator-owned integration and authorized CI execution.
