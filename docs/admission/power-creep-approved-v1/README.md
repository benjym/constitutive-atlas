# Power-creep acceptance and website integration

The user instructed: “Ok let's accept into the atlas and put it on the website,
then commit and push”. [approval.json](approval.json) records that authorization
and the exact reviewed/tested model bytes. The registry retains existing approvals
and adds this bounded both-active specialization. [Current dossier](../../models/power-creep-itasca900-both-active-ode.md)
explains scope and exclusions. The historical model and numerical packets remain
unchanged; original website/server bytes are archived in `prior-source/`.

The dedicated browser laboratory is linked from the Atlas navigation and model
catalogue. It uses relative asset URLs for GitHub Pages' project prefix and
publishes the approval record, agent review and hashed engine/model identity.
The public strain-path runtime remains a distinct interface. Scientific-release,
experimental calibration and full threshold-family claims are excluded.

[WEBSITE_PLAN.md](WEBSITE_PLAN.md) and [website-freeze.json](website-freeze.json)
freeze analytical package checks before runtime observation. CI builds the
separate power-creep target serially and packaging runs both default10s histories
against independent scalar references, along with asset/identity checks.

[source-retention.json](source-retention.json) records durable ignored local
retention of the exact private extracted source text; raw copyrighted source is
not published. The private receipt describes extracted text, not original HTML.
Run `python3 -B docs/admission/power-creep-approved-v1/check.py` for public approval
and packet integrity checks; add `--private` to check local source retention.
