# Generic outer-control derivative partition consistency

CAP-control-partition-derivative-v1. Design only, no runtime edits, builds or compiled calls. The exact failed MD1997 coarse-control trace is retained under docs/ingestion/manzari-dafalias-1997/delivery-v1/control-trace-actual-v1/. Existing studies, failures, source definitions and gates remain immutable.

## Problem established by actual evidence

Protocol1 computes its radial-stress finite difference using two independently adaptive constitutive integrations from the same committed state. In the exact retained trace, the trial uses one accepted substep and the perturbation uses two. The resulting difference spans distinct discrete maps and changes the apparent slope from the independently source-supported positive~78.7MPa to-723.3MPa. Every ensuing one-substep line-search evaluation increases the residual. Independent source BE roots exist and outer control is smooth. The failure is numerical partition inconsistency, not absent constitutive roots or permission to relax final yield feasibility.

Protocol3 has the same source-code pattern: trial `integrate` at an isochoric axial control, then a separately adaptive integration at an added1e-8axial/-5e-9radial perturbation. Thus it has the same structural vulnerability. No actual protocol3 failure is asserted. A shared generic policy can cover both derivatives, but protocol3 needs its own synthetic and ordinary regression evidence before integration.

## Recommended smallest bounded implementation

First implement a bounded same-partition finite-difference probe. Keep the existing initial finite-difference amplitudes, outer30iteration cap, strict residual-descent line search, physical constraints, rollback semantics and control acceptance tolerance. The base trial always comes from the unchanged `integrate` operation. Accept a derivative probe only if it succeeds and its accepted partition is comparable to that base trial. If it fails or has a different accepted partition, halve its directional amplitude, through at most10halvings (11probes total, minimum base_h/1024). Abort with the existing control failure if no comparable representable probe exists. Never use an unmatched endpoint to form the derivative. An invalid/nonfinite/nearzero derivative retains current failure behavior; it does not authorize an unbounded search for a desired sign.

Protocol1 direction is [0,1,1,0,0,0], initial h=max(1e-9,abs(axial)*1e-3). Protocol3 direction is [1,-.5,-.5,0,0,0], initial h=1e-8. Directional denominator must be the actual selected h, not the original amplitude. Keep all probes from the same committed state and pass the unchanged settings/parameters to each call. Probes cannot commit history. Their diagnostics must not be spliced into the accepted trial's material update or budget accounting. The additional per-derivative call bound is explicit; it does not increase material max_depth/max_substeps or outer iteration bounds.

This can be implemented as one local helper near `controlled_step`, plus one partition-comparability helper. No header inclusion or generated schema changes are required. Parent must supply an explicit runtime whitelist before implementation. The relevant source is `cpp/include/atlas/solver.hpp`; no model-specific branch belongs in this change.

## Comparable accepted partition: precise audit

Do not compare only substep counts. Both successful advances must have complete nonempty `increment_fractions` and `accepted_increments`, with matching lengths; every increment has six finite entries. Their `partition_retries` identities must match. Compare every accepted fraction bit-for-bit (or exact double equality for finite positive values, which excludes signed zero), in order. Require finite positive fractions and coverage sum within the existing1e-12accepted-partition coverage convention. The corresponding actual increments must be an affine extension of the base accepted increments under the total perturbation:

`probe_step[i][j] ~= base_step[i][j] + fraction[i]*(probe_total[j]-base_total[j])`.

Use a local floating arithmetic audit bound of8*epsilon*max(abs(base_step),abs(probe_step),abs(fraction*delta_total)), with8*denorm_min floor solely for underflow. This is a binary-affine consistency check, not a constitutive acceptance tolerance. In unchanged total components require exact equality, avoiding an unrelated stress/strain magnitude floor. Reject incomplete diagnostics, NaNs, differing non-dyadic retry identities, unequal ordered fractions, or failed affine audits. A bound on coverage alone does not establish matching partitions.

The current recursive solver stores every actual accepted strain tensor for implicit and midpoint paths. Alternate residual retry reweights the accepted fractions by the left/right1/3and2/3branches while preserving their actual binary increments. Those actual increments are necessary: a non-dyadic selected partition is an affine branch about its stored base values, not simply a guarantee that multiplying each rounded fraction by the new total reproduces its actual binary increments. The existing `linearize_update` documents that same fixed-affine interpretation. Comparing raw accepted increment arrays for equality across perturbed totals would wrongly reject every nonzero probe; comparing normalized components by division would fail at zero channels and small magnitudes.

This policy matches the adaptive partition topology and its affine values. It does not certify that every constitutive `select`/absolute-value/reset branch is identical or that a mathematical derivative exists at a constitutive kink. Those issues already exist in finite-difference control and remain fail-closed under existing nonfinite, nearzero derivative and no-descent rules. Do not advertise the result as an analytic algorithmic tangent.

## Alternatives and why not include them in this bounded patch

Fixed accepted-partition replay has stronger deterministic semantics: prepare the parent once for the perturbed total, then apply exactly the base accepted node sequence with values `actual_base_step+fraction*delta_total`, calling `implicit_step` or the existing midpoint update with no adaptive reselection. Verify the unperturbed replay reproduces the accepted base endpoint, preserve reset scope and reject any perturbed replay that fails physical/domain constraints. This avoids the inability to find a nearby matching adaptive partition. However, it adds a second integration path, new replay failure/budget/diagnostic semantics, and must separately cover rate models, residual transients, reset guards and non-dyadic partitions. It is a distinct capability if bounded shrinking cannot qualify the exact regression. Do not silently fall back to it or modify a model to avoid mismatch.

Direct AD of the accepted discrete update already exists in `linearize.hpp`, but that header includes `solver.hpp`. Calling it directly from `controlled_step` in `solver.hpp` would create an include-layer cycle. Refactoring integration/control/linearization to reuse it is materially broader than the observed defect. Do not copy the AD implementation into solver.hpp or replace tangent semantics as part of this bounded fix.

Bounded shrinking may fail at an exact partition boundary, where every positive perturbation selects another topology, or near a material branch/singularity. That honest failure is preferable to an unmatched finite difference. It may also add up to11integrations per derivative; operation bounds are therefore part of review. Whether it resolves the actual MD1997 failure must be established by unchanged compiled regression after implementation, not promised by this design.
