# Generic exact Mandel determinant core v1 — prospective study

This study tests a new generic numerical core, not a clay-specific kernel. Existing DSL/compiler/tensor evaluation and model definitions are unchanged. Registering the operation and testing executed-expression failure/AD routing remain subsequent gates before model use.

The mathematical input is six exact binary64 values in orthonormal Mandel order x,y,z,u,v,w. The determinant is A+B sqrt(2), where A=xyz-(xv²+yw²+zu²)/2 and B=uvw/2. Exact dyadic arithmetic retains every product, shift and cancellation. For opposite signs, comparison of a+b sqrt(2) to a rational boundary reduces to exact integer comparison of a² and2b², with sign conditions established before squaring. No rounded square-root coefficient enters the result. Approximate floating candidates only guide the search: exact midpoint checks certify each selected rounding cell; otherwise monotone binary search covers all nonnegative finite binary64 patterns. Ties select the even significand; final rounded zero is canonical+0; final rounded overflow rejects.

The Jet derivative is the exact cofactor contraction at the stored primal with each stored seed vector, independently rounded. It differentiates the mathematical determinant, not the rounding map. All six inputs and228seeds must be finite even for zero coefficients. Compute the primal and all38directions into a candidate before assigning caller output. A rejected final component leaves all output bits unchanged. Exact intermediate arithmetic may exceed binary64 range while a finite final answer succeeds.

The C++ integer representation uses unsigned32bit limbs. A multiplication accumulation is at most (2^32-1)^2+2(2^32-1)=2^64-1. Carry words target previously untouched positions; shifts use disjoint bit ranges and subtractions require established magnitude order. Finite triple products/halves and up to nine summed derivative terms require fewer than approximately6400magnitude bits; squared comparisons require fewer than12800. Signed int exponents and dynamic limb vectors cover this range without truncation. Memory allocation failure may throw; output remains unassigned. Fast-math/finite-math-only builds are explicitly rejected because they can invalidate finite-input checks. Output rounding remains nearest-even regardless of the approximate guide's evaluation order/rounding. Performance is unoptimized and unqualified.
