# Proposed generic solution-state constraint contract — not implemented

Add an optional explicit `solution_constraints` list to the relevant v0.3 incremental-residual model profile. Each expression must be Boolean and depend only on current persistent state, material parameters and I; no loading, prior state, physical time, increment-local multipliers or unqualified derived aliases. Dimensions and restricted expression syntax use the existing DSL. Source constraints must be mapped in the dossier; this field is not a fitted numerical tolerance or a list of arbitrary caller callbacks.

`domain` continues to state where the residual expression can be evaluated. `solution_constraints` states what persistent physical states may be accepted. A residual can have a useful mathematical extension outside the physical solution set. The two scopes must be explicit; do not silently repurpose initial checks (which may encode preparation-only conditions) or infer solution constraints from the form of equations.

The proposed Tresca follow-up would restore the v2 residual domain and add `principal_range_le(sigma,2*k)` as a solution constraint. Its exact-root-set argument is unchanged: every exact return already lies in C. No stress or plastic-strain component is manually projected or overwritten. Initialization/parent validation must reject a supplied state violating the constraint, while a raw residual/Jet request can still evaluate the original extension probes. The existing finite-primal/seed checks and sticky expression failures must remain intact.

At runtime, the generic constraint callback/checker must be called on initial/parent physical states, feasible Newton/backtracking trial states, converged steps and final committed states. Reject a failed constraint before accepting or committing the state. Preserve the entire incoming state on rejection and same-instance recovery. Raw residual and derivative evaluation must remain independent of the solution constraint; observables or laboratory paths that claim a physical state must validate it. Existing models without the optional field retain their current behavior. Unsupported rate/time profiles must be rejected explicitly rather than assumed covered by incremental-residual evidence.

Keep generated headers/catalogues byte-identical when no model uses this feature. The compiler can conditionally emit the new checker/callback binding; the shared engine needs a generic fallback for older generated catalogues. No Tresca identifier or handwritten constitutive kernel is permitted. Archive hash-bound schema/model/compiler/solver source before editing; keep existing evidence and private candidate identities immutable.

Qualification must include typed negative cases for non-Boolean, dimension errors, forbidden prior/loading/time/transient symbols, malformed/nonfinite state/parameter inputs, actual callback failure and recovery. Demonstrate that a physically invalid state rejects at initialization/commit while the same raw residual extension still evaluates. Retain all 61 original cases/all 38 derivative columns and all 12 continuous increments, the unchanged independent references, original tolerances/iteration limits, strict source-invalid restart rejection, and real tentative-state/full rollback. Native then Wasm each use a single serial explicit target. A distinctly identified follow-up candidate must pass both full subgates before claiming the interface issue resolved.

This proposal separates two meanings already exposed by the v3 result; it does not retroactively pass v3, admit a model, or extend the scientific source domain.
